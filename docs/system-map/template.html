Facundo · architecture at a glance

Facundo System Map

Two products share one repo. Discovery & Recruiting finds and signs florist shops. Production takes a real Shopify order, places it with a florist, pays the split against a delivered photo and writes the result back to Shopify. The order loop below is generated from dashboard/lib/lifecycle.ts, the same file that renders /lifecycle.

The order loop, end to end

Cold-offer bridgeA shop still in the funnel can be offered a real order. That is a Production decision.
Working-set gateEvery order is ingested. Only orders matching an active tag or picked by staff are matched, offered and escalated automatically.
Where a person steps inThe CX desk gathers unplaceable orders, held cold offers, stalled offers, late photos, held payouts and escalated support threads into one queue. In semi mode each step waits for approval. Accept-leg and delivery-leg payouts never wait.
Layer 3 · the decision

How one shop is chosen

This is the Match stage drawn out. It runs in match.ts, one shared file that both the worker and the dashboard use.

NO AI

No AI model picks the shop. The choice is a fixed rule that anyone can recompute. The same order and the same shops always give the same ranking, and each candidate is saved with the score breakdown that put it there. Every number below is a setting in Settings → Matching. If a setting is missing or broken, that one value falls back to its default, so a bad row can never stop matching.

1

Find shops near the address

Look inside a box around the delivery point, as wide as the 20 km cap, across every city.

2

Drop who can't take it

  • Test shops
  • Denylisted or lost
  • No trust tier, so we can't pay them
  • Below the rating floor (off by default)
  • Distance unknown, or past their radius
  • Already full for that day
3

Sort by distance ring

0–5 km, then 5–10 km, then 10–20 km. A shop in a nearer ring always ranks above one further out, whatever their scores.

4

Score inside each ring

Inside a ring, a weighted score decides the order. The weights are in the table below.

5

Keep the top 3

Merge duplicate listings of one shop and shops sharing one inbox. Save the best 3 as ranked candidates for the order.

Example: three shops around one delivery

C is past the cap and is dropped in step 2. A shop that says it covers 50 km is still held to 20 km. A shop that gives no radius is treated as covering the full 20 km.

autoIf the top candidate has joined us, the offer goes out at once. If the top candidate is a prospect, it must pass the cold-offer gates, or it waits for a person to approve.
semiCandidates are saved but nobody is contacted. The order stays at “received” until CX approves the match on the order page, or approves escalation if nobody qualifies.
manualCandidates are saved and a person sends each offer. The wave engine only keeps offers fresh and escalates. In every mode, if nobody is in range, an ingest of the area is requested while there is still time.

Cold-offer gates

A shop that never joined is offered automatically only when all of these pass. Otherwise the offer waits for approval.

Cold offers enabledSettings
Payout at or under the ceilingSettings, default €120
At least 6 hours to deliveryHard-coded

Automation modes

manual A person sends each offer. Waves only keep offers fresh and escalate.
semi The system proposes match, offer, reassign, customer emails and write-back. A person approves each.
auto The wave engine runs unattended, up to the wave limit, stopping a reserve window before delivery.

Money

The trust tier sets the split, 70/30 by default or paid in full. The total floors to a whole euro. The accept leg pays on acceptance and the delivery leg on the photo, in every mode.

Reply agent → guard decidesThe model sorts the message into an intent and drafts a reply. A separate fixed rule decides whether to send it. Complaints, opt-outs, live order changes, money questions and requests for a person always go to a human. After a set number of replies a human takes over anyway.
Photo check → recorded, not trusted with moneyAn audit of past verdicts found the check not yet reliable enough to hold real payouts. The verdict is saved for review. The delivery leg is released on upload.
Translation → English on any doubtShopify's own translations come first. A model fills only the rest, and any failure or check miss leaves the line in English.
Recruiting copy → template fallbackThe approved text comes from the catalog. The model only adapts language, name and opener. Any failure sends the plain template.

Staff tools outside the loop also use models: the statistics chat (read-only database role) and draft translations in the message editor, which a person reviews before they go live.
